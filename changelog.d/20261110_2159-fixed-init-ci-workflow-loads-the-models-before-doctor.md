- **The workflow `pnk init --ci` writes no longer fails its health check on a cold model cache.** `pnk doctor` loads models offline and downloads none (0.32.9), and `pnk sync` loads only the embedder, so on a fresh runner the workflow's `pnk doctor` step failed on the models (the reranker, or both when the KB had no documents), because the weights were cached nowhere. The workflow now caches `~/.cache/huggingface` under a key of its own and runs one `pnk search warm-up -k 1 > /dev/null` before the health check, which loads both models online; its output is discarded because a search prints passage text and an Actions log can be public. Measured on an empty model cache, `pnk doctor` exited 1 before that search and 0 after it, with 30 documents and with none. **The workflow installs `pinakes[light,pdf]`, so it needs a manifest that names `fastembed`**: pass `--backend light` to `init`, or edit the manifest. **A workflow written earlier is never updated**, since `init` never overwrites one: add a cache step for `~/.cache/huggingface` before the sync, and a `pnk search warm-up -k 1 > /dev/null` step after the sync and before the health check, as the [`pnk init` reference](https://github.com/lucagattoni/pinakes/blob/main/docs/CLI.md#pnk-init) says.
