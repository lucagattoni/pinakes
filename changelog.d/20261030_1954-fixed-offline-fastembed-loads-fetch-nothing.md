- **`pnk doctor`, and every other `--offline` model load, no longer downloads a model or ends in a traceback when one is missing from the cache.** For the `fastembed` provider, measured 20261019 against the published 0.32.7: with the embedder cached and the reranker not, `pnk doctor` printed *Fetching 5 files*, took 11 s and grew the cache from 67 MB to 1.1 GB, because the only guard (`_require_online_or_cached`) asked whether the cache *directory* existed; with `HF_HUB_OFFLINE=1` it fetched nothing and exited 1 on `ValueError: Could not load model BAAI/bge-reranker-base from any source`, which `doctor`'s `except PinakesError` does not catch. The comment that said fastembed has no `local_files_only` was stale: 0.8.0 (the floor in `pyproject.toml`) takes it through `**kwargs` into its download step, so an offline load now passes `local_files_only=True` and any failure of that load becomes an `EmbeddingError`, whether fastembed's `ValueError` for a model that is absent or onnxruntime's `InvalidProtobuf` for one that is cached but truncated. Reproduced 20261030 with the real fastembed against an empty temporary cache directory, the network forbidden: both loaders reached `model_info` before, and raise `EmbeddingError` with nothing reached and no file written after; the real `pnk doctor` on a KB stamped `--backend light`, same setup, reached the network on its first model load before, and after it printed two `FAIL` lines, exited 1, made no network attempt and left the cache holding only its empty `hub`. **The error is classed by its cause.** What the library says is absent (a `FileNotFoundError`, or fastembed's `ValueError: Could not load model …`) keeps its old wording and remedy (*Run once without --offline to populate the cache.*). Every other failure (onnxruntime's `InvalidProtobuf` for a truncated download, a `PermissionError`, a `MemoryError`, a `TypeError` from a changed signature) reads `--offline was requested but <model> could not be loaded (<Class>: <first non-empty line>).`, claims nothing about the cache, and gives the remedy *Fix the cause named above; if the model's files are damaged, delete its folder under <cache> and run once without --offline.*, because going online cannot repair a damaged model: fastembed looks at the local snapshot first online too, and fails the same way. The missing-directory message is unchanged, and the online path of every loader makes the same call it always did. The same loaders serve `search`, `ask`, `sync`, `links` and `serve` with `--offline`, so they change together. Also fixed: fastembed's local-only path leaves an empty `<cache>/tmp` that `hf cache scan` warns about, and the loader now removes it when it made it and it is still empty. **Measured, for a minimal model:** a test plants a hand-encoded one-node ONNX graph and a tokenizer in a Hugging Face layout cache and loads them with the real fastembed and onnxruntime, offline and online, the network sealed: the same `info()` and token count, nothing reached, the cache tree unchanged. **Not measured:** real weights offline. The `model`-marked tests, which run in CI, call the loaders with `offline=False` only. **The default provider, `sentence-transformers` (`[st]`), gets the same classed failure, and for it only reading and stand-in tests back the claim.** Its two loaders pass `local_files_only=offline`, which the wheel and the keyword's name say keeps them from downloading; that is read, not run, and no test has seen the real package refuse a download. What they lacked was a `PinakesError`. **Read, never run:** the 5.6.1 wheel (the version `uv.lock` pins) was fetched alone, with no dependencies, unzipped and read, and neither it nor torch was installed. In it, `load_file_path` catches the Hub's `LocalEntryNotFoundError` and returns `None`, so a model absent from the cache falls through to `_load_default_modules`, whose `AutoConfig.from_pretrained(..., local_files_only=True)` is transformers' to fail. **transformers was not read**, so which class a miss ends in is unverified (an `OSError` from memory, not from a source), and the loaders convert any `Exception` rather than guess one. If transformers raises a plain `OSError` and not a `FileNotFoundError` for a missing model, which nothing here has checked, a missing sentence-transformers model is told *could not be loaded* with the delete-the-folder remedy instead of *Run once without --offline*. **Measured:** nothing about the real package. Its tests put a stand-in `sentence_transformers` module in `sys.modules`, so they pin what the loader does with an exception and say nothing about what sentence-transformers raises; they also pin the call, unchanged, online (`local_files_only=False`) and offline (`revision`, `local_files_only=True`, `cache_folder`). One shared helper builds the message for all four loaders. The words `doctor` uses to tell a user what to do next are unchanged (finding F3), and on a fastembed miss the library itself still logs two `ERROR` lines to stderr.
