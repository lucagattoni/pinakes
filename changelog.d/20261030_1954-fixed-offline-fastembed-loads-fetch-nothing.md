- **`pnk doctor`, and every other `--offline` load with the `fastembed` provider, no longer downloads a model or ends in a traceback when one is missing from the cache.** Measured 20261019 against the published 0.32.7: with the embedder cached and the reranker not, `pnk doctor` printed *Fetching 5 files*, took 11 s and grew the cache from 67 MB to 1.1 GB, because the only guard (`_require_online_or_cached`) asked whether the cache *directory* existed; with `HF_HUB_OFFLINE=1` it fetched nothing and exited 1 on `ValueError: Could not load model BAAI/bge-reranker-base from any source`, which `doctor`'s `except PinakesError` does not catch. The comment that said fastembed has no `local_files_only` was stale: 0.8.0 (the floor in `pyproject.toml`) takes it through `**kwargs` into its download step, so an offline load now passes `local_files_only=True` and any failure of that load becomes an `EmbeddingError`, whether fastembed's `ValueError` for a model that is absent or onnxruntime's `InvalidProtobuf` for one that is cached but truncated. Reproduced 20261030 with the real fastembed against an empty temporary cache directory, the network forbidden: both loaders reached `model_info` before, and raise `EmbeddingError` with nothing reached and no file written after; the real `pnk doctor` on a KB stamped `--backend light`, same setup, reached the network on its first model load before, and after it printed two `FAIL` lines, exited 1, made no network attempt and left the cache holding only its empty `hub`. The online path makes the same call it always did, and the error keeps its wording and its remedy (*Run once without --offline to populate the cache.*), so `doctor` prints its FAIL line instead of a traceback. The same loaders serve `search`, `ask`, `sync`, `links` and `serve` with `--offline`, so they change together. Also fixed: fastembed's local-only path leaves an empty `<cache>/tmp` that `hf cache scan` warns about, and the loader now removes it when it made it. **Not measured:** a run against real weights, because a download and the maintainer's own cache were off limits for this change; `tests/test_embed.py`'s `model`-marked tests, which run in CI, are the check on a model that is really there. Two things are unchanged on purpose: the `sentence-transformers` loaders (they already pass `local_files_only`), and the words `doctor` uses to tell a user what to do next (finding F3). On a miss fastembed itself still logs two `ERROR` lines to stderr. A new battery, `tools/batteries/src-pinakes-embed.toml`, carries nineteen mutants of this change, all nineteen killed in one run (0 survived, 0 errored), the first of them by the sealed test's own `_NetworkReached: model_info`.
